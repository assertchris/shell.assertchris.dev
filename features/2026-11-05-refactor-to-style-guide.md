# Apply Brand Style Guide to shell.assertchris.dev

## Overview

We're going to apply the assertchris.dev brand style guide to `shell.assertchris.dev`. The `@tailwindcss/typography` plugin goes, and in its place we get hand-authored brand tokens and `.article` styles. We'll also add a logo component and a scheme switcher, so the layout matches the other assertchris.dev properties.

## Phase 1: CSS tokens and app.css

**Files:** `resources/css/tokens.css` (new), `resources/css/app.css`

Steps:

1. Create `resources/css/tokens.css`. It holds the brand color tokens for light and dark modes, registered as Tailwind theme values via `@theme inline`. Here's the file:

```css
/* Generated by brand:generate — do not edit directly */

:root {
    --color-background: var(--color-stone-50);
    --color-background-secondary: var(--color-stone-200);
    --color-foreground: var(--color-stone-900);
    --color-foreground-secondary: var(--color-stone-500);
    --color-accent: var(--color-blue-600);
    --color-on-accent: var(--color-stone-50);
}

.dark {
    --color-background: var(--color-stone-950);
    --color-background-secondary: var(--color-stone-800);
    --color-foreground: var(--color-stone-200);
    --color-foreground-secondary: var(--color-stone-400);
    --color-accent: var(--color-blue-400);
    --color-on-accent: var(--color-stone-900);
}

@theme inline {
    --color-background: var(--color-background);
    --color-background-secondary: var(--color-background-secondary);
    --color-foreground: var(--color-foreground);
    --color-foreground-secondary: var(--color-foreground-secondary);
    --color-accent: var(--color-accent);
    --color-on-accent: var(--color-on-accent);
}

@layer components {
    .type-heading { font-family: var(--font-sans); font-size: var(--text-2xl); font-weight: var(--font-semibold); color: var(--color-foreground); }
    .type-heading-secondary { font-family: var(--font-sans); font-size: var(--text-xl); font-weight: var(--font-semibold); color: var(--color-foreground); }
    .type-heading-tertiary { font-family: var(--font-sans); font-size: var(--text-lg); font-weight: var(--font-semibold); color: var(--color-foreground-secondary); }
    .type-content { font-family: var(--font-sans); font-size: var(--text-sm); font-weight: var(--font-normal); color: var(--color-foreground); line-height: 2; }
    .type-content-secondary { font-family: var(--font-sans); font-size: var(--text-xs); font-weight: var(--font-normal); color: var(--color-foreground-secondary); line-height: 2; }
    .type-label { font-family: var(--font-sans); font-size: var(--text-xs); font-weight: var(--font-semibold); color: var(--color-foreground-secondary); }
}
```

2. Update `resources/css/app.css`:
   - Add `@import './tokens.css';` after the tailwindcss import
   - Remove `@plugin "@tailwindcss/typography";`
   - Add `@custom-variant dark (&:where(.dark, .dark *));`
   - Leave the `@source` directives alone
   - Leave the `@theme { --font-sans: ... }` block alone
   - Add an `@layer base` block with `.article` styles for every element the markdown renderer outputs

Before we remove the plugin, we need to check that Filament's own CSS in `resources/css/filament/` doesn't import `@tailwindcss/typography` on its own. If it does, removing the plugin here will break typography over there.

**Tests:** Run `npm run build` and confirm there are no CSS errors.

## Phase 2: Logo Blade component

**Files:** `resources/views/components/logo.blade.php` (new)

Steps:

1. Create `resources/views/components/logo.blade.php` as an anonymous Blade component that contains the assertchris logo SVG. It takes optional HTML attributes through `$attributes->merge()`. The stroke colors come from the CSS variables `--logo-stroke-start` and `--logo-stroke-end`, which switch when the `.dark` class is applied.

Templates will reference it as `<x-logo />`.

**Tests:** We'll check it visually once the layout rewrite in Phase 3 is done.

## Phase 3: Layout rewrite (docs.blade.php)

**Files:** `resources/views/components/layouts/docs.blade.php`

Steps:

1. Add a dark-mode flash-prevention script in `<head>`, before the stylesheet loads. It reads `localStorage.getItem('color-scheme')` and applies the `.dark` class to `<html>` synchronously. This stops the page flashing light before dark mode kicks in.
2. Rewrite `<body>` to use the `bg-background type-content` brand token classes.
3. Add a `<header>` row containing:
   - Logo link: `<x-logo />` wrapped in `<a href="{{ route('docs.index') }}">`
   - Site name link: `<a class="type-heading-secondary no-underline">Shell</a>`
   - Scheme switcher: `<div id="scheme-switcher">` with Light / System / Dark buttons, pushed right with `ml-auto`
4. Keep the two-column layout: a `<nav>` sidebar (`w-56 shrink-0`) next to the `<article>` content area.
5. Switch the nav links to `type-label no-underline`, and use brand token classes for the active and hover states.
6. Change `<article>` from `class="prose prose-blue max-w-none min-w-0 flex-1"` to `class="article flex flex-col gap-4 min-w-0 flex-1"`.

The prop signature stays as it is: `@props(['title', 'pages', 'currentSlug' => null])`.

**Tests:** Run `npm run build`. Open `/docs` in a browser and check that the header renders, the scheme switcher toggles dark mode, and the sidebar active state works.

## Phase 4: Scheme switcher JavaScript

**Files:** `resources/js/app.js`

Steps:

1. Append the scheme switcher JS below the existing `import './bootstrap';` line. The script:
   - Reads `localStorage.getItem('color-scheme')`, falling back to `'system'`
   - Adds or removes `.dark` on `<html>`, based on the stored preference and the `prefers-color-scheme` media query
   - Adds `bg-foreground/10` to the matching `[data-scheme]` button so the active one shows
   - Listens for button clicks and for changes to the `prefers-color-scheme` media query

**Tests:** Confirm in the browser that all three modes (Light / System / Dark) toggle correctly and persist across a page refresh.

## Phase 5: Dependency cleanup

**Files:** `package.json`

Steps:

1. Remove `"@tailwindcss/typography": "^0.5.19"` from `devDependencies` in `package.json`.
2. Run `npm install` to update `package-lock.json`.
3. No `composer.json` changes are needed.

**Tests:** Run `npm run build` and make sure there are no missing module errors.
